# AGENTS.md

Guidance for coding agents working in this repo.

## What this is

npm-workspaces monorepo for "Doodle DS", a playful neo-brutalist React design system (Tailwind v4, React 19).

- `packages/tokens` → `@doodle-ds/tokens` — DTCG token JSON → Style Dictionary → CSS variables
- `packages/ui` → `@doodle-ds/ui` — components + Tailwind theme (the publishable package)
- `packages/icons` → `@doodle-ds/icons` — "Scribbles" wobbly icon set (`ICONLIST.md` = plan + status)
- `apps/docs` → `@doodle-ds/docs` — docs/showcase site, consumes the two packages via workspace links
- `brand/` — logo SVGs and avatar PNGs; root-level `*.png` files are throwaway verification screenshots

## Commands

```sh
npm run build          # tokens → icons → ui → docs, IN THIS ORDER (chained at root)
npm run build -w @doodle-ds/ui   # single package
npm run dev            # docs dev server (vite)
npm run typecheck      # tsc in every workspace
npm run check          # lint, typecheck, unit tests, production audit, build
npm run verify         # check plus Playwright browser smoke tests
npx changeset          # versioning flow (ui + tokens versioned; docs ignored)
```

Verification = `npm run check` plus `npm run test:e2e`; browser tests use the built docs site through `vite preview`.

## Hard-won gotchas

- **Build order matters.** `ui` imports `@doodle-ds/icons` dist, and `docs` imports built artifacts (`@doodle-ds/ui` dist, `@doodle-ds/tokens/css/tokens.css`). Building docs without building tokens/icons/ui first fails. Always use the root `npm run build`, not `--workspaces`.
- **Style Dictionary: one output file only.** Multiple `files[]` entries with the same `destination` silently overwrite each other — the whole `tokens.css` (primitives `:root`, semantic `:root`, `.dark` overrides) must come from a single registered format (`sd.config.mjs`, format `css/ds-tokens`).
- **Style Dictionary v4 helpers** live in `style-dictionary/utils` (`usesReferences`, `getReferences`), not the main export. DTCG `$value` is NOT exposed as `.value` — read `token.$value ?? token.value` in custom formats.
- **Token naming contract:** raw palette = `--ds-color-*`, semantic = `--ds-*` (`semantic.`/`dark.` path prefixes are stripped in the format). Semantic references resolve to `var(--ds-color-*)`, so `.dark` re-theming works at runtime.
- **Components must use semantic vars only** (`--ds-bg`, `--ds-ink`, `--ds-line`, `--ds-sun`, Tailwind names `bg-bg`, `text-fg`, `border-line`, `bg-accent-*`). Never raw hex. Dark mode = `.dark` class on `<html>`; brand theming = override `--ds-*` vars.
- **`packages/ui/src/styles/theme.css` is the single source** for `@theme`, keyframes, and custom utilities (`rounded-wobbly`, `squiggle`, `bg-noise`, `shadow-pop*`). The docs app compiles its own Tailwind and cross-workspace imports this file plus `@source` scanning of `packages/ui/src` — new component classes flow automatically, but @theme/@utility changes must go in `theme.css`.
- **`@/` alias only exists in the docs app.** `packages/ui` source uses relative imports (`../lib/cn`) so it can build standalone via tsup.
- **CSS subpath imports need the file extension** in TS: `@doodle-ds/tokens/css/tokens.css` works (matches `vite/client` `*.css` types); `@doodle-ds/tokens/css` fails `tsc`.
- **Interactive components use Radix primitives** (`radix-ui` unified package: Dialog, Tooltip, Tabs) wrapped with the doodle skin — don't hand-roll a11y for new interactive components. Checkbox/Radio/Switch intentionally stay on native inputs. Tabs panels must be nested inside `<Tabs>` (Radix Root); `TabPanel` takes `value`, not `active`.
- **Icons are codegen'd.** `assets/svg/*.svg` is the single source of truth; `src/icons/*.tsx` and `src/index.ts` are generated by `scripts/generate.mjs` on every build — never edit generated files by hand. Icon style rules (2px stroke, wobble, 16px review) and the tier checklist live in `packages/icons/ICONLIST.md`.
- **`@doodle-ds/ui` depends on `@doodle-ds/icons`** (declared in its package.json, kept external by tsup) — components import icons from the package name (`@doodle-ds/icons`), never inline SVGs or emoji glyphs. Still no relative cross-package imports.
- **Visual style rules are non-negotiable:** 2px ink borders, hard offset shadows only (`shadow-pop*`, never blur), wobbly border-radius, no smooth color gradients. Pattern-only texture utilities may use radial/repeating CSS patterns. Palette and rules live in `brand/`.

## Verify visually

Playwright CLI works for screenshots (`npx playwright screenshot --full-page --viewport-size "1600,1000" <url> out.png`). No image-analysis MCP is guaranteed to be connected — don't claim visual verification from a screenshot you can't inspect.
